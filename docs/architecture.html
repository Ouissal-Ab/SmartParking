Pourquoi des « route groups » (public), (user), (admin) ?

Les parenthèses en App Router permettent de regrouper des pages sans préfixer l'URL. Elles servent surtout à fournir un layout dédié :

  • (public)/page.tsx → URL / (pas de sidebar/navbar)
  • (user)/layout.tsx → wrap chaque page utilisateur avec <Navbar />
  • (admin)/layout.tsx → wrap chaque page admin avec <AdminSidebar />

Hard nav avec window.location.href vers /dashboard ou /admin — garantit que les cookies fraîchement écrits sont vus par le middleware sur tous les navigateurs (notamment Safari mobile).
Pourquoi localStorage ET cookies ?
  • localStorage → lu côté client par axios pour mettre l'Authorization header
  • cookies → lu côté serveur Edge par middleware.ts avant le rendu

5 · Client API (lib/api.ts)

const api = axios.create({ baseURL: computeBaseUrl(), withCredentials: true });

computeBaseUrl() est dynamique :

  • Page sur localhost → API = http://localhost:8080
  • Page sur IP LAN (mobile) → API = http://<même-IP>:8080

Cela permet à un téléphone qui scanne le QR de joindre le backend sans config manuelle.

Deux intercepteurs :

  • Request : ajoute Authorization: Bearer <token>
  • Response : sur 401, nettoie la session et redirige vers /login

6 · Middleware Edge

matcher: ['/admin/:path*', '/dashboard', '/reserve/:path*',
          '/reservations', '/payment', '/confirmation']
  • /admin/* → cookie role doit être ADMIN, sinon redirige /dashboard
  • Routes utilisateur → cookie token requis, sinon redirige /login?redirect=<url-origine>

7.4 Trois sources de publication côté backend

  1. ReservationService.createFromRequest() — après save place en RESERVE
  2. PlaceService.updateStatus() — quand un admin change manuellement
  3. ReservationScheduler.updateReservations() — toutes les 60 s, libère les places des résa expirées

7.5 Client singleton (lib/realtime.ts)

const client = new Client({
  webSocketFactory: () => new SockJS('http://<host>:8080/ws'),
  reconnectDelay: 3000,
  heartbeatIncoming: 10000,
  heartbeatOutgoing: 10000,
});
  • reconnectDelay — se reconnecte automatiquement après 3 s
  • heartbeat — ping de chaque côté pour détecter une coupure silencieuse (Wi-Fi mobile)
  • Re-souscrit automatiquement aux topics actifs après reconnexion

API publique :

function subscribeTopic<T>(topic: string, handler: (msg: T) => void): () => void

Retourne une fonction unsubscribe. Plusieurs handlers peuvent s'abonner au même topic — un seul subscribe STOMP est ouvert.

7.6 Hook React

export function useLivePlaces(handler: (u: PlaceUpdate) => void) {
  useEffect(() => {
    const unsub = subscribeTopic<PlaceUpdate>('/topic/places', handler);
    return unsub;
  }, [handler]);
}
Le handler doit être stable (utilisez useCallback), sinon il se réabonne à chaque rendu et perd les messages.

9 · QR de handoff mobile

Composant : components/MobileHandoffQR.tsx.

  1. Récupère window.location.pathname
  2. fetch('/api/lan-ip') → {ip: "192.168.x.x"}
  3. Remplace localhost par cette IP
  4. Rend <QRCodeSVG value={url} />

Route serveur app/api/lan-ip/route.ts — lit os.networkInterfaces() et renvoie la première IPv4 non-internal.

11 · Comment ajouter une page

  1. Créer app/(user)/ma-page/page.tsx avec 'use client' si interactif
  2. Ajouter le lien dans components/layout/Navbar.tsx
  3. Mettre à jour middleware.ts matcher si protégée
  4. API : import api from '@/lib/api' → await api.get(...)
  5. Temps réel : import { useLivePlaces } from '@/lib/hooks/useLivePlaces'

12 · Comment ajouter un topic WebSocket

Backend

@Service
@RequiredArgsConstructor
public class MonPublisher {
  private final SimpMessagingTemplate template;
  public void send(MonDto dto) {
    template.convertAndSend("/topic/mon-topic", dto);
  }
}

Frontend

// lib/hooks/useMonTopic.ts
import { useEffect } from 'react';
import { subscribeTopic } from '@/lib/realtime';

export function useMonTopic(handler: (msg: MonDto) => void) {
  useEffect(() => subscribeTopic<MonDto>('/topic/mon-topic', handler), [handler]);
}
